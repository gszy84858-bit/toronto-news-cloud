# 多伦多新闻早报 · 云端版

每天自动生成多伦多 / GTA 新闻早报，跑在 GitHub 服务器上，**不依赖任何个人电脑开机**。

📖 **第一次使用请看 [`部署指南.md`](部署指南.md)**（从零到你手机主屏上一个枫叶图标，约 15 分钟）。

---

## 结构

```
toronto-news-cloud/
├── .github/workflows/daily.yml   定时任务：每天 12:00 UTC（多伦多上午 8:00，冬令时 7:00）
├── generate.py                   主程序：抓取 → 筛选 → 分类 → 配图 → Gemini 中文 → 渲染
├── build_site.py                 把 output/ 构建成 docs/（首页 / 往期 / 搜索 / 分享）
├── notify.py                     邮件推送（未配置密钥则自动跳过）
├── 本地验证.sh                    在 /tmp 副本里跑完整流程，不弄脏仓库
├── 配置手册.md                    改参数看这份（不用碰代码）
├── app-icon.png                  手机主屏图标
├── config/
│   ├── preferences.json          条数 / 时间窗 / AI / 告警关键词 / 邮件
│   ├── sources.json              新闻源清单（14 个已实测可用）
│   └── rules.json                分类体系与性质判定关键词
├── output/                       历期早报母本（.md + .html），CI 自动提交
└── docs/                         发布产物（不进 git，每次由 CI 重建后直接发布）
```

## 现在有哪些功能

| 功能 | 说明 |
|---|---|
| 每日 10 条中英对照 | 中文标题 + 摘要 + 配图，每条标注分类与性质 |
| **生意告警置顶** | 命中关税/罢工/利率等关键词的条目置顶并标 `⚡ 影响生意` |
| **每条配图** | 取自原文（RSS 媒体字段 → 正文图 → 原文页 og:image） |
| **站内搜索** | 往期全量可搜，支持 `?q=关键词` 与分类筛选 |
| **转发** | 系统分享面板；分享链接指向本站该条（含锚点） |
| **邮件推送** | 每天部署完成后自动发送（需配 `MAIL_*` Secrets） |
| 版本自愈 | 手机缓存旧页面会自动拉最新版 |

## 零依赖

只用 Python 3 标准库 —— 不需要 `pip install` 任何东西，因此流水线里没有依赖安装步骤，
也就不会因依赖变动而挂掉。Gemini 走原生 REST（`urllib`），不需要 SDK。

## 手动本地运行

```bash
export GEMINI_API_KEY=AIza...        # 不设也行，会回退成英文
python3 generate.py --force --stats  # 生成到 output/
python3 build_site.py                # 构建到 docs/
```

## 设计上的几个坑（已修，改动时别踩回去）

1. **首页必须原地输出内容，不能跳转。** iOS「添加到主屏幕」会固化添加时的网址；
   若根网址跳转到带日期的文件，主屏图标会被永久锁死在那一天。
   所以 `index.html` = 最新一期的完整正文。
2. **重跑当天必须排除当天的旧文件。** 跨期去重会扫描最近 3 天的早报，
   若不排除当天，重跑时早报会把自己全部去重掉，产出一份空日报。
   （`prev_report_index(..., exclude_date=今天)`）
3. **自动重试必须计数。** 页面一刷新 JS 就重置，不把次数存进 `sessionStorage`
   就会变成每 45 秒无限刷新的循环。上限 8 次/天/会话。
4. **时区必须锁定 `America/Toronto`。** Runner 是 UTC，不锁定会把日期和时间写错。
5. **大模型判定优先于规则引擎。** 规则按关键词匹配容易张冠李戴，所以 AI 成功后
   会先清空规则给的 `biz_advice`，由模型判断（不相关时返回空字符串）。
6. **`docs/` 绝对不能进 git。** 它和云端每天都会改同一批文件，一旦入库，
   合并时就会把两版页面拼在一起，`<<<<<<< HEAD` 直接上线（踩过两次）。
7. **工作流里"打包"必须在"归档"之前。** 顺序反了，`git pull --rebase` 的冲突标记
   会跟着被打包发布；另有发布前 grep 闸门兜底。
8. **代码里的模型名会过期。** 每次运行先查 ListModels 拿真实可用模型，
   失败自动切备用供应商（DeepSeek），不要硬编码。

## 切换到其他大模型

改 `config/preferences.json`：

```json
"ai": {
  "provider": "openai",
  "base_url": "https://api.deepseek.com/v1",
  "api_key": "",           // 建议留空，用环境变量注入
  "model": "deepseek-chat"
}
```

代码无需改动 —— `ai_enrich_openai()` 走标准 `/chat/completions` 协议。
